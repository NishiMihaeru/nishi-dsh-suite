# The Grok Build CLI contract, and what a `grok` route would rest on

Read on 2026-09-04, **before any grok route code existed**, in the same form as `agy-cli-contract.md` and `claude-code-cli-contract.md`. It exists so the transport decision could be argued from the vendor's published surface rather than settled after the code was written, which is the failure this repository has already paid for twice (`ROADMAP.md` §5, §7d). `packages/grok` was then built on it the same day and is covered by findings 14 and 15; every row below still describes the vendor rather than the package.

It was written to answer one question the maintainer asked directly: **integrate the Grok CLI, or reach Grok through opencode?** The answer is at the end, and it rests on the inventory rather than on preference.

Read against the installed build:

```text
grok 1.0.13 (5e9a58528b76) [stable]   /usr/bin/grok
```

That is a distribution package, **not** the vendor's managed install at `$GROK_HOME/bin/grok`. The difference matters for one published behaviour: the stdio agent skips its background self-update unless it runs from the managed install, and the machine additionally carries an admin policy file (finding 11).

## What the vendor actually publishes

**Headless entry.** `-p/--single`, `--prompt-file` or `--prompt-json` runs one prompt non-interactively and exits. Four output formats: `plain`, `json` (one object at the end), `streaming-json` (NDJSON of the agent's own ACP session updates), and `streaming-messages-json` (**NDJSON in the Anthropic Messages API wire format** — `system`/`init`, `assistant` with `text`/`thinking`/`tool_use` blocks, `user` with `tool_result` blocks, terminal `result`). Both streams are documented as **read-only**: "Tool approvals and other bidirectional flows use the ACP interface".

**Spend, per invocation.** `json` and the terminal `result` carry `usage` with `input_tokens` (uncached only), `cache_read_input_tokens`, `cache_creation_input_tokens`, `output_tokens`, `reasoning_tokens`, `total_tokens`, plus `num_turns`, `modelUsage` per model, `total_cost_usd` and `total_cost_usd_ticks` (1 USD = 10^10 ticks). Incompleteness is typed rather than zero-filled: `usage_is_incomplete` and `cost_is_partial` suppress every cost float rather than let a consumer sum a fake bill. `modelUsage.*.contextWindow` carries the current model's real window.

**Sessions.** `-s/--session-id` creates a **new** session under a client-chosen UUID (errors if malformed or already in use); `-r/--resume` resumes by id or title; `-c/--continue` takes the most recent session for the cwd; `--fork-session` branches. Transcripts live in `~/.grok/sessions` as per-cwd SQLite.

**Tool control.** `--tools` (allowlist) and `--disallowed-tools` (denylist) are headless-only; denylist wins where both name a tool. `--disallowed-tools` also takes `Agent`, `Agent(explore)` forms to block subagent spawning, and `--no-subagents` does it wholesale. `--disable-web-search` removes web search and fetch. Tool names are internal ids (`run_terminal_command`, not `bash`). The final toolset is documented as "requested tools plus always-on MCP meta-tools".

**Permissions.** `--allow`/`--deny` take `ToolPrefix(glob)` rules (`Bash`, `Edit`, `Write`, `Read`, `Grep`, `WebFetch`, `MCPTool`), deny beats allow, and they gate execution rather than removing tools. `--permission-mode` takes `default`, `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan`. `--always-approve`/`--yolo` is `bypassPermissions`.

**Prompt shaping.** `--system-prompt-override` replaces the agent's system prompt, `--rules` appends, `--verbatim` sends the prompt exactly as given, `--max-turns N` bounds the agent's own loop (`N >= 1`), `--json-schema` constrains the reply and implies `--output-format json`.

**ACP.** `grok agent stdio|serve|leader|headless` speaks JSON-RPC (Agent Client Protocol) with `session/new`, `session/prompt`, `session/update`, permission requests, and an `x.ai/*` extension family (fs, git, worktree, search, terminal, session fork, rewind, compact, auth). `session/new` accepts per-session `mcpServers` and `_meta.systemPromptOverride`; `--plugin-dir` injects a per-process, always-trusted plugin directory whose hooks and MCP servers activate without a prompt, and which the vendor says its own SDKs use for per-connection injection.

**Quota surface.** `24-monitoring-usage.md` is an OpenTelemetry export for fleet operators, not a quota read. `/usage` is documented under *Account and Billing* as a TUI action ("View credit usage or manage billing"), and it is absent from the session's advertised command list — `grok -p "/usage"` is not a counterpart to `agy -p "/usage"`. The machine-readable channel is ACP `_x.ai/billing` after `initialize` on `grok agent stdio`: no session, no turn (finding 18).

## The terms, and which of them bite

Read on 2026-09-04, closing the debt this file opened. Four published documents govern, and one shipped file settles a question the other three do not touch.

**Which agreement applies is not a judgement call.** The binary carries exactly two legal URLs — `x.ai/legal/terms-of-service` and `x.ai/legal/privacy-policy` — and the route this file designs authenticates the way finding 12 measured, `apiKeySource: "oauth"` against a grok.com login. So the **Consumer** Terms govern it, with the AUP applying "to anyone using our Service, including consumers, developers and businesses" by its own first line. The Enterprise Terms govern the `XAI_API_KEY` path instead, and they are the only place a distribution right lives (below).

**The client is Apache-2.0.** `/usr/share/licenses/grok-build-bin/LICENSE` is the Apache License 2.0 under "Copyright 2023-2026 SpaceXAI", and `~/.grok/README.md` says so in its own words. That is a permissive licence over the **client**, and a materially better starting point than either vendor this repository already drives. It licenses no part of the Service behind it — the ToS and AUP do that, and nothing below is softened by it.

**Automated and scripted access is invited, in the vendor's own documentation.** The README's second sentence is "Use it interactively as a TUI, or integrate it into your own apps via headless mode and the Agent Client Protocol (ACP)"; `14-headless-mode.md` is titled *Headless Mode and Scripting* and ships CI/CD, pre-commit-hook and Python-wrapper examples; `15-agent-mode.md` names "IDEs, SDKs, eval harnesses, and custom apps" as the intended clients. That matters because the AUP prohibits "Accessing the Services through **unauthorized** automated or non-human means, whether through a bot, script, or otherwise" — the operative word is the qualifier, and published documentation is what supplies authorization. Recorded honestly rather than favourably: a second AUP bullet lists "using bots to access" inside a sentence whose tail is "or otherwise seek to obtain the source code of our Service", so it can be read either as a standalone bot-access ban or as one more way of reaching the source. Under the stricter reading the answer is the same — driving the official binary through its own published headless and ACP interfaces is authorized by the vendor that published them — and under either reading a route that reached the *service* by some private channel instead of the published client would not be.

Four obligations bite, and they bite the package rather than the design.

| # | Clause | What it costs us |
|---|---|---|
| 1 | Consumer ToS §2: "You may not share your account credentials or make your account available to anyone else, and are responsible for all activities that occur under your account" | Already this repository's hard rule. Sign-in stays inside `grok`; nothing reads `~/.grok/auth.json`, nothing proxies or pools an account, and each user drives their own installed binary under their own login. The Enterprise Terms' *Bundled Service* right — develop integrations against the APIs and distribute them to End Users — exists only on the API path and needs a Customer relationship and an Order Form. **The consumer path grants nothing similar, which is exactly why the route must stay "the user's own binary, the user's own login".** We also do not redistribute the CLI, the same posture Codex and Antigravity already hold |
| 2 | AUP: "Disrupting, interfering with, or unauthorized access to the Service or its safety systems, including **circumventing any rate limits** or restrictions or protective measures" | The published reason for a concurrency cap and for bounded retries, the way condition 4 is for Claude. A route that answers a 429 by spawning more children is the shape this clause names |
| 3 | AUP: "Using the Service or any Output to develop (or assist anyone in developing) machine learning models **or any products or services that compete with SpaceXAI, whether directly or indirectly**" | **The one that needs a maintainer decision.** Grok Build is xAI's own agent harness and Nishi DSH Suite is an agent harness, so the clause is at least arguably in scope. The two readings differ in where the line falls: a user routing their own DSH session to Grok is consuming the Service, not developing with its Output, whereas writing this package's code *with* Grok Build would be using Output to build something adjacent to the vendor's own product. The cheap way to keep the clause untouched is a rule rather than an argument — **do not use Grok Build to author the grok provider package, and do not carry its Output into this repository.** Recorded, not decided |
| 4 | Brand Guidelines, under **Don't**: "Use our Marks in any app title, domain name, or the name of any product or service not made or provided by us", and "Use our Marks in or as part of your marks"; logos usable "only ... exactly as provided ... without any alteration" | **Settled and against us, identically to `nishi-dsh-claude`.** An npm package named `nishi-dsh-grok` puts the mark in the name of a product xAI does not provide. The sanctioned form is the factual reference the same page permits — "Use our Marks only to accurately refer to us or our services" — so "drives the official Grok Build CLI" in plain text is fine and the package name is not. Ship a neutral glyph rather than anything derived from the mark. Consumer ToS §4 says the same thing from the other side: using SpaceXAI's "name, logos, trademarks, or other brand elements" requires permission |

Two further clauses are noted because they are easy to trip over later rather than because they bind the design. The Brand Guidelines ask that Grok-generated text or images be attributed ("Written with Grok" / "Created with Grok") "wherever the Grok-generated material is published or distributed" — DSH displays Output to the user who prompted it and publishes nothing, so this bites only if this repository ever ships Grok-authored material, which rule 3 already forbids for a different reason. And the AUP forbids "Offering the Service in a region where we do not offer the Service"; DSH offers nothing, the user brings their own account.

**Verdict.** Nothing published forbids the route as designed. There is no clause here equivalent to Anthropic's requirement that a distributor agree to separate Commercial Terms, because we distribute nothing and the user's own installed client is the only thing touching the Service. What the terms do settle is the package's name and icon, and what they leave open is one maintainer decision on the competing-products clause.

## Findings from this pass

Free probes first; the six turn-spending ones are marked.

**1. `--tools ""` is silently a no-op, and that is the trap in this whole surface.** *(turn)* An empty allowlist does not remove the tools; `system`/`init` reported the **full 25-tool set** — `run_terminal_command`, `read_file`, `search_replace`, `write`, `spawn_subagent`, `web_search`, `image_gen` and the rest — and the prompt cost **13,423 uncached input tokens**. The spelling that reads as "give it nothing" gives it everything, without a warning. Claude Code's `--tools ""` does the opposite, so the analogy from `claude-code-cli-contract.md` row 5 does **not** transfer.

**2. A one-name allowlist works, and two flags together reach zero built-ins.** *(turn)* `--tools "read_file"` yielded exactly `read_file`, `search_tool`, `use_tool` and dropped the prompt to **4,860** tokens. `--tools "read_file" --disallowed-tools "read_file"` yielded `search_tool`, `use_tool` alone — the two always-on MCP meta-tools the documentation names — at **4,442** tokens. So the isolation posture is expressible on the command line with no agent file, no workspace scaffolding and no user-owned configuration, which is what Antigravity needed `.agents/agents/dsh-primary.md` for. With no MCP server configured the two survivors address an empty registry.

**3. `--json-schema` binds, and it binds again after a resume.** *(2 turns)* Turn 1 returned `structured_output = {"kind":"message","text":"I'm Grok 4.5, built by xAI."}` and the same JSON as `result.result`. Turn 2, in a **separate process** resuming the same session, returned `{"kind":"message","text":"banana"}`. This is the ambiguity that row 10 of the `agy` inventory is built around, and here it did not reproduce: nothing went stale, because each invocation is its own process and its own result. The vendor also publishes an `error_max_structured_output_retries` result subtype, which says enforcement is a bounded retry loop rather than constrained decoding — the same class as `agy`, but with a **published failure code** instead of a silent miss.

**4. Cross-process resume keeps the prefix cache.** *(same 2 turns)* Turn 2 reported `input_tokens: 140` against `cache_read_input_tokens: 4480`. The whole reason `packages/antigravity` holds a live `agy` child per DSH session — that a fresh process cannot hit the vendor's cache — **does not apply to this vendor**. One short-lived process per DSH step is both the simple design and the cached one.

**5. Usage is per invocation, not cumulative.** *(same 2 turns)* Turn 2 reported its own 140/11, not the session's running total. Antigravity's contract-mandated subtraction (`agy` row 4) has no counterpart to write here.

**6. `--prompt-json` accepts ACP content blocks only — there is no `tool_result` block.** *(free)* The parser's own rejection: "unknown variant `tool_result`, expected one of `text`, `image`, `audio`, `resource_link`, `resource`", and the envelope accepts exactly one type, `"acp"`. So a DSH tool result cannot be handed back in the vendor's own tool-result shape through the headless entry. It has to travel as content, which is the same constraint the `agy` bridge envelope lives under.

**7. An embedded `resource` block reaches the model verbatim.** *(turn)* A prompt of one `text` block plus one `resource` block (`uri: "dsh://tool-result/call_1"`, `mimeType: "application/json"`, `text: {"marker":"GROK_PROBE_7731"}`) came back with exactly `GROK_PROBE_7731`. So finding 6's constraint has a typed remedy: results ride as addressed JSON resources rather than as prose quoted into a user message, which is strictly better than what this repository does for Antigravity today.

**8. `/usage` is not a quota channel.** *(turn)* `grok -p "/usage"` was **not** interpreted as a command: it reached the model as prose, which began narrating a lookup and ended `stopReason: "cancelled"` after 13,420 input tokens. `/usage` is absent from the session's advertised `slash_commands`. `/context` *is* advertised, is recognized in headless, and renders **nothing** — empty text, `end_turn`, no spend fields, i.e. a TUI-only command that reached the model not at all. This finding remains true of that spelling. The channel that *does* exist is finding 18.

**9. The ACP handshake publishes the model catalog, the context window and the reasoning efforts — free, with no session and no turn.** *(free)* `initialize` returned `modelState.availableModels` with `grok-4.6` and `grok-4.5`, each carrying `totalContextTokens: 500000`, `supportsReasoningEffort: true`, and an effort list (`low`, `medium`, `high` default, plus `xhigh` on 4.6 only). Two Antigravity debts have no counterpart here: the context window is disclosed rather than deployment-guessed at 200 000, and efforts are a first-class dimension rather than three suffixed catalog ids to collapse. `initialize` also publishes `authMethods`, `agentVersion` (so finding 15 of the `agy` file — a failed turn must name the vendor build — costs no extra process here), a hooks capability with blocking `pre_tool_use`, and `x.ai/pluginDirs: true`.

**10. The routed model id is not the catalog id.** *(turn)* `modelUsage` keys reported `grok-4.5-build` where the request named `grok-4.5`. Any usage normalization keyed on the requested id will miss.

**11. This machine carries an admin policy that refuses `--always-approve`.** *(free)* `/etc/grok/requirements.toml` — shipped by the distribution package — pins `[sandbox] profile = "workspace"`, `[ui] permission_mode = "ask"`, `disable_bypass_permissions_mode = true`, `[features] telemetry = false`, `remote_fetch = false`, and 23 bash deny rules. `grok agent --always-approve stdio` exits printing `always-approve disabled by managed policy`. For a route where **DSH executes every tool** this is irrelevant, and that is itself an argument for that shape: a transport that needs the vendor to auto-approve its own tools is one admin policy away from not running.

**12. Auth is the subscription, not an API key.** *(free)* `grok models` reports "You are logged in with grok.com"; `system`/`init` reports `apiKeySource: "oauth"`. Cost is nevertheless stamped on OAuth traffic here (`total_cost_usd: 0.009185576` on probe 1), which the documentation says is often omitted on pool/OAuth paths.

**13. Every headless invocation leaves durable residue.** *(free)* `~/.grok/sessions` holds one directory per URL-encoded cwd plus `session_search.sqlite`; the probes created two new cwd directories. This is Codex's residue debt, not Claude's `--no-session-persistence` freedom: there is no documented flag to suppress it, only a read-only `~/.grok` mount, which the vendor documents as "session persistence fails silently".

**14. The `json` envelope spells the decision `structuredOutput`, not `structured_output`.** *(turn)* The documentation names `structured_output` "snake_case, matching the schema" -- for the `streaming-messages-json` `result` line, which is the format it happens to document. The `json` envelope this route reads returns `structuredOutput`. Both spellings are read, and the reply text is parsed as the schema-bound JSON if neither field is present, which is safe because the stamp is verified either way.

**15. The whole transport works end to end on the real vendor.** *(4 turns, the live suite)* `pnpm test:live:primary` passes 4/4 against `grok 1.0.13`, read from its own exit code: the handshake publishes the catalog, window and efforts with no turn; the **shipped argv** leaves `system`/`init.tools` holding nothing but the two MCP meta-tools; a turn answers under the forced schema; and a tool result delivered by `--resume` in a new process is read back by the model *and* arrives with a non-zero `cache_read_input_tokens`. The last one is the load-bearing scenario: it is the live evidence for finding 4, and the reason this package holds no live vendor child.

**16. `cancelled` is the vendor's word for two different endings, and one of them is a turn-cap exhaustion.** *(turn, and the first real DSH request)* A step run with `--max-turns 1` came back `stopReason: "cancelled"`, `structuredOutput: null`, `structuredOutputError: "model did not produce structured output"`, exit `1`, and `Error: max turns reached` on stderr. Read from the envelope alone that is indistinguishable from a user cancellation, and reporting it as one tells the DSH loop the wrong thing about who ended the turn. The stderr line is the only discriminator, so it is now a recogniser and the settlement takes stderr.

**17. An embedded `resource` is readable in isolation and a liability in front of an agent.** *(3 turns)* Finding 7 stands as measured -- a lone resource block was read back verbatim. It does not survive contact with a real request. Handed DSH's 29-tool catalog and a 6.5 KB agent system prompt, the model's first thought was "I need to read the attached JSON resource", and it spent its round on that: with a one-round cap the step died, and with a cap of four it answered with a `read` call on the envelope and a `turn` stamp it had invented -- the signature of a payload it never actually read. The identical envelope as a plain `text` block answered correctly, with the correct stamp, at a cap of one. The route now sends text, and the transport rules say the envelope is inline with nothing to fetch. **The general lesson is worth more than the finding**: a capability probed on a bare prompt says what the vendor can do, not what a model will do when it is holding tools.

**18. `_x.ai/billing` is the quota channel finding 8 said did not exist.** *(free)* After ACP `initialize`, with no `session/new` and no prompt, `grok agent stdio` answers `_x.ai/billing`. On `grok 1.0.13` the result carried `config.creditUsagePercent` (a used percentage, not remaining) and `currentPeriod` of type `USAGE_PERIOD_TYPE_WEEKLY` with start/end. `subscription_tier` was absent on this build (Omarchy reports it on 1.0.5). Prepaid/on-demand fields arrived as `{val: 0}` with no unit. The method is a vendor extension, not in the representative `x.ai/*` tables of `15-agent-mode.md`; a rename looks from here like a signed-out CLI, so a missing percentage is `UNAVAILABLE` rather than zero. Prior art: [Omarchy PR 6485](https://github.com/omacom/omarchy/pull/6485) drives the same method and never reads `auth.json`. This package does not take that collector's log fallback.

**19. Inline `--prompt-json` / `--json-schema` / `--system-prompt-override` die with `E2BIG`, and a per-tool `anyOf` schema is what a real session ended with no structured decision.** *(production, then free probes)* A DSH session failed `Grok CLI turn produced no structured decision` (`end_turn`, empty `structuredOutput`) and the rebuild died `spawn E2BIG`. Linux `MAX_ARG_STRLEN` is 128 KiB per argument; `--prompt-json` was the envelope, `--json-schema` was a 29-way `anyOf` of full parameter schemas copied from `agy` before this vendor's subset was probed, `--system-prompt-override` was transport rules plus DSH's system. `--prompt-file` is the published file form of `-p`. `--json-schema` does **not** accept a path (a real file path is `invalid JSON`). `--system-prompt-file` does not exist (`unexpected argument`). `--prompt-json @file` is also invalid JSON. Live turns with a tiny schema succeed; the production failure was `end_turn`, not turn-cap, which is the signature of a schema the vendor did not enforce rather than a retry that ran out. The route now writes the envelope to `--prompt-file`, pins tool names without `anyOf`, and puts DSH's system in the envelope.

## What was built on it

`packages/grok` ships exactly this shape: per DSH step, one `grok --prompt-file ... --resume <session>` process, with `--tools <one name> --disallowed-tools <same name>` for isolation, `--system-prompt-override` carrying the transport rules only, `--json-schema` carrying a flat decision schema that pins tool names and leaves arguments untyped, `--prompt-file` delivering the step's envelope as the user-message text (findings 16, 17 and 19 are why it is text, why the cap is not `1`, and why it is a file), and `--max-turns 4`. DSH's system instruction rides in the `full` envelope. Per-turn spend comes from the invocation's own `usage`; the catalog, the 500k window and the effort list come from a turn-free ACP `initialize`; Usage & Limits comes from `_x.ai/billing` on that same stdio entry, still with no session.

What that did **not** need, compared to `packages/antigravity`: a live vendor child, envelope negotiation against a process, usage subtraction, a repair envelope, a deployment-guessed context window, a model-family collapse, and an ~800-line quota harvester. What it needed that Antigravity does not: a regression test pinning finding 1.

Kept from that route rather than dropped: the delivered-prefix digest check, the per-step stamp (finding 3 says it cannot currently go stale here; it is three lines and the failure it guards is silent), the all-or-nothing decision check, and DSH-minted call ids with the vendor's own id restored on the wire. Per-tool argument typing was dropped: finding 19.

## Probe hygiene

Every probe ran from a scratch directory outside this repository (`/tmp/claude-1000/.../scratchpad/probe`), on `grok-4.5` at `--reasoning-effort low`, against `grok 1.0.13`. Six turns were spent; the five that carried a stamped cost sum to `0.0259` USD, and the sixth (finding 7) reported spend with the cost floats omitted, which is the documented behaviour rather than a free turn. Nothing was written to `~/.grok` beyond what the vendor writes by itself: two session directories and their SQLite index (finding 13), which is the residue being reported rather than an artefact to clean. No configuration was mutated, no MCP server was registered, no `grok mcp add` was run, and `/etc/grok/requirements.toml` was read and not touched. The ACP probes killed their child after reading the handshake. These probes are exploratory and are not retained as a suite; the recipes are in the findings above.

## Consequences

1. **The comparison that prompted this file is settled by rows 1-11 against row 12.** Reaching Grok through opencode means a second full agent harness between DSH and the model — opencode owns its own loop, tools, permissions and compaction — so DSH's tools would have to re-enter through MCP, which is the transport this repository removed on evidence (`ARCHITECTURE.md`, *Antigravity tool transport*). It also loses finding 12: opencode reaches Grok on an xAI API key or its own billing, and a route paid by token has no reason to drive a CLI at all rather than the OpenAI-compatible xAI API. The `grok` binary is the only one of the two that carries the subscription. **Integrate `grok` directly** -- done, as `packages/grok`.
2. **DONE, and finding 1 is still the single most dangerous thing in this file.** It is pinned twice: `packages/grok/test/argv.test.ts` asserts the shipped argv names the isolation tool in BOTH flags, and `test-live/primary.test.ts` asserts against the real vendor's `system`/`init.tools` that nothing but the two MCP meta-tools survives. `--tools ""` reads as total isolation and delivers a 25-tool agent with shell and file write. The `claude` analogy actively misleads here.
3. **ACTED ON.** Findings 3, 4 and 5 together deleted most of the Antigravity transport's complexity rather than porting it: `packages/grok` has no live vendor child, no `agy-session.ts` counterpart, and no usage subtraction. What was kept is listed under *What was built on it*.
4. **Row 16 is closed, and it did not block the design — it named the package.** The terms read landed the same day this file was written. Two items come out of it and neither touches the transport: `nishi-dsh-grok` is non-compliant by the Brand Guidelines' own **Don't** list, which is the *second* provider in this repository to hit that rule after `nishi-dsh-claude`, so the naming decision is now one decision for both rather than two; and the competing-products clause wants a maintainer answer, with the cheap mitigation already written down (do not author this package with Grok Build). The clause Anthropic has and xAI does not — a distributor agreeing to separate Commercial Terms — has no counterpart, because nothing here is distributed.
5. **Row 10 is the pattern to watch, and it is now pinned.** `packages/grok/test/model-catalog.test.ts` asserts a recorded handshake, so a rename fails a test rather than a session. Restated, because the reason matters more than the test: The richest instrument this vendor offers — a turn-free catalog with the real context window and the effort list — is undocumented. That is the same shape as Codex's `dynamicTools` and `agy`'s per-turn schema: load-bearing, unpublished, and therefore owed a test that fails loudly when the vendor renames it.
6. **Row 12 closed the same way Antigravity's finding 5 did.** Finding 8 was right that `/usage` is not a channel. Finding 18 found `_x.ai/billing` on the ACP surface the catalog already drives. `packages/grok` now declares the usage capability from that method. Prepaid/on-demand `{val: 0}` fields are not projected, because nothing names a unit. Omarchy's collector ([PR 6485](https://github.com/omacom/omarchy/pull/6485)) is prior art for the method name and the "Grok owns the call" boundary; this package does not take its log fallback.
7. **Finding 19 closed the argv.** A real DSH session died `spawn E2BIG` on a rebuild after `end_turn` with no structured decision. `--prompt-file` is the published file form; `--json-schema` and `--system-prompt-override` have none. The per-tool `anyOf` schema copied from `agy` is also what that turn failed to satisfy. The route now writes the envelope to a file, pins names without `anyOf`, and puts DSH's system in the envelope.
